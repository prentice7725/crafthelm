# Architecture Decision Records (Initial M0 Baseline)

| ADR | 결정 | 이유 |
|---|---|---|
| ADR-001 | 새 저장소 `crafthelm` | 기존 `hyperfusion`을 독립된 상태로 유지하기 위함 |
| ADR-002 | 단일 공급자·한 개 CLI로 완결 | 실무 도입 장벽과 복수 구독 의존을 줄이기 위함 |
| ADR-003 | Native-first, 자체 LLM 브로커 배제 | 중복 구현과 운영 복잡도를 줄이기 위함 |
| ADR-004 | Lead의 직접 작업은 예외로 허용 | 작은 작업에서 위임 오버헤드가 커지는 것을 막기 위함 |
| ADR-005 | 방법론 네 설정 조합 | 생명주기·명세·엔지니어링·실행 범위를 서로 다른 차원으로 다루기 위함 |
| ADR-006 | 계약 승인 후 Full Loop | 자율 실행과 사용자 통제를 함께 보장하기 위함 |
| ADR-007 | 자동 기술 검증 + **사람의 최종 인수 승인** | 기술적 PASS와 책임 있는 완료 판단을 분리하기 위함 |
| ADR-008 | 외부 Skill 허용목록과 버전 고정 | 재사용과 함께 공급망·권한 통제를 지키기 위함 |
| ADR-009 | 검사 기준 자동 완화 금지 | Learning Loop에서 검사 기준을 낮춰 통과하는 왜곡을 막기 위함 |
| ADR-010 | M0 실측 우선, 기능 확장 후순위 | 근거 없는 엔진 비대화를 막기 위함 |
| ADR-011 | Kouetsu를 사람용 문서 교열 스킬로 재사용 | 독자가 치르는 해석·검증 비용을 줄이기 위함 |
| ADR-012 | 문장 교열과 시각적 레이아웃 렌더링 분리 | Kouetsu의 실제 기능 범위와 맞추기 위함 |
| ADR-013 | 자동 완료는 `READY_FOR_HUMAN_REVIEW`까지만 | 인간의 최종 책임을 기계적 증거와 구별하기 위함 |
