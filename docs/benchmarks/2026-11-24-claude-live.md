## 읽는 법

- **품질:** 세 비교군 모두 숨은 검사를 통과했다. 과제가 작아 품질 차이를 가르지 못한다. 품질 비교에는 더 어려운 과제가 필요하다.
- **비용:** B의 워커 비용은 A의 약 51%다. sonnet이 opus보다 단가가 낮기 때문이다. B에는 리드 토큰이 들어 있지 않으므로(`lead_tokens: unknown`) 실제 CraftHelm 세션 비용은 이보다 크다. 이 수치로 절감률을 주장하지 않는다.
- **C가 A와 같은 이유:** C의 비용이 A와 거의 같다. 이 환경의 기본 모델이 opus였을 가능성이 높지만, 이 실행은 실제 모델을 기록하지 않았으므로 확인된 사실은 아니다.
- **시간:** B와 C는 인터뷰·계약·검증 단계 때문에 A보다 과제당 3~10초 느렸다.
- **표본:** 비교군당 과제 3개, 1회씩이다. 모델 출력은 실행마다 달라진다.

## 이 실행으로 드러난 측정 결함과 수정

1. **입력 토큰이 10~14로 보고됐다.** Claude CLI의 `input_tokens`는 캐시에서 읽은 프롬프트 토큰을 빼고 센다. Claude Code 호출은 시스템 프롬프트가 커서 실제 입력은 대부분 캐시 읽기(호출당 17만~26만)다. 기존 보고서 표에는 이 값이 없어서 입력이 거의 없는 것처럼 보였다. 캐시 생성 토큰(`cache_creation_input_tokens`)은 아예 수집하지 않았다.
2. **"host default" 실행의 실제 모델을 알 수 없었다.**

수정 후 Claude 어댑터는 `cache_creation_tokens`와 `models_used`(CLI 출력의 `modelUsage` 키)를 함께 기록한다. 보고서 표에는 캐시 읽기·쓰기 열과 실제 사용 모델 열이 생겼다. 위 표는 수정 전 실행이라 캐시 생성 토큰과 실제 모델이 없다. 다음 실측부터 채워진다.
